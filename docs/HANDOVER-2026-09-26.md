## Tracked follow-up (user decision at merge: as-is)

- **Cold-start flow-collection race** (final-review Important finding, narrow reachability): the
  three Room-backed getter flows (`summaries`, `hasOpenSession`, `clubs`) are collected from the
  first composition frame, racing `LaunchedEffect(sessionRepository) { initializeAndRestore() }`.
  If a first query throws, the app can crash at launch before recovery engages; if corrupt-DB
  recovery swaps the database, the already-captured flows die with the closed DB and History /
  club picker / END SESSION stay empty until the next restart. Fix (~10 lines, AppRoot only): a
  `repoReady` flag set at the end of the existing restore effect, each collection gated as
  `remember(sessionRepository, repoReady) { if (repoReady) sessionRepository.summaries else flowOf(emptyList()) }`
  (same shape for `hasOpenSession` and the three `clubs` sites), so post-recovery re-capture fetches
  a fresh flow from the rebuilt DB. **Make this the first post-merge commit.**
